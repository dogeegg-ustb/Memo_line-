## 1. 定位与产品约束

记艺线是 CLIP STUDIO PAINT（CSP）的**外挂式**录制与编辑工具：

- **录制**：记录数位笔/键鼠的原生机械事件，同时截图识别 CSP 各面板状态（笔刷、子工具、图层、颜色、画布视口、历史记录），并在画布视口变化处保存 `.clip`、导出图层、计算脏矩阵，形成可追溯的“聚集事件包”。
- **编辑**：录制中按 Alt+M，在冻结的 CSP 画面上框选区域，执行
  - **精确撤销**：只撤销当前图层中与选区相关的笔画（及其叠放闭包），其余历史不动；
  - **事件编辑**：让选中的历史笔画不再发生，或换笔刷/属性后重放。
- **封盘**：停止录制后把两份运行时流合并成一个可校验的 `.memoline` 容器，同一工程的多次录制续写在同一文件中。

贯穿全局的约束：

| 约束 | 含义 |
|---|---|
| 不注入 CSP | 不做 DLL 注入、渲染钩子（杀毒、权限、EULA、崩溃风险）；状态只来自截图 OCR、保存的 `.clip` 文件和 CSP 配置文件。 |
| 原始记录不可改写 | 机械字节、已提交的聚集包、脏矩阵、图像资产都是固定内容；只有“维度”可新增算法版本。 |
| 发给他人使用 | 安装与初始化须自动完成，不依赖本机特有的软件（如 Sunshine/ZakoVDD、AutoHotkey）。 |
| 不伪造证据 | 未知就是未知（`null`/`unknown`），失败保留原因，不用旧值或默认值冒充当前观察。 |

## 4. 录制子系统

### 4.1 原生录制器 BehaviorRecognizer（C#）

主要组成（`src/BehaviorRecognizer/`）：

| 组件 | 职责 |
|---|---|
| `Capture/UnifiedInputCapture`、`OtdInputSource`、`WindowsInputHooks`、`WindowsMouseInputRouter`、`InputEventNormalizer`、`InputEventBus` | 统一采集 OTD 数位板报告或 Windows 笔/鼠/键事件，归一化为 `penBegin/penSample/penEnd`、键鼠帧；带 `RecorderInputTag=0x4D4C5243`（"MLRC"）的合成输入在入口丢弃。 |
| `DriverInitializationService`、`DisplayCalibration` | 应用数位板驱动映射；多屏时用悬停校准自动选定数位板对应的显示器（5 次匹配，3 px 内）。 |
| `CspWindowProbe`、`IInputTargetProbe` | 判断指针下窗口是否属于 CSP，决定输入是否算作绘画。 |
| `LayerSaveGuard` | 图层面板点击或图层命令键前，进程内 SendInput 发 Ctrl+S（`beforeLayerOperation`），松开约 40 ms 后再补存一次（`afterLayerOperation`；弹出菜单时记 `clipSaveSkipped`）。 |
| `RecorderInputControlServer`、`EditingInputControl`、`RecorderStateRequest` | 控制管道 `memoline-recorder-input-<pid>`（见 §7.2）：状态请求、保存请求、编辑边界、编辑事务、录制结束、输入拦截。 |
| `UpdateActivatorBridge` | 启动并驱动 Python 集成子进程；主动状态请求带 `afterEventId`，避免请求后的截图被判为因果歧义。 |
| `Session/SessionManager`、`Storage/Memoline` | 会话生命周期；用 `Memoline.Core` 的 `MemolineWriter` 追加 `.memoline.part`，写 `.memoline.live.json` 接口描述。 |

机械流帧：`MemolineEvent(AppendId, Path, Kind, EventId, Ticks, AppendedTicks, OperationId, RelatedEventIds, DeviceSource, Data)`。

- `appendId` 每帧递增，`eventId` 只对硬件帧递增，`operationId` 为一次接触的 `penBegin` eventId。
- 写入线分为 `hardware`、`immediate`（触发、截图、保存请求）、`delayed`（`coreStateUpdated`、`clipParseResult`）。
- 每次笔下落固定 `penDownLocation`（笔刷属性/工具组/工具栏/导航器/图层/画布视口/其他），按当时工作区面板 ROI 分类。
- 延迟状态按“预留位置”定序：触发时在 Writer 锁内预留 `packageId/afterEventId/reservationOrder`，结果成功后才追加 `statePackageReserved` + `statePackageResult`；失败只写 `*.diagnostics.jsonl`。

### 4.2 集成层 recorder_integration（Python）

| 模块 | 职责 |
|---|---|
| `runtime.py` | 录制器拥有的无激活覆盖层进程，stdin/stdout JSONL 通信；布局轮询（0.5 s）、面板边框、主动状态请求。 |
| `setup_ui.py` | 唯一可获得焦点的初始化界面：选择 `.clip`、驱动配置、冻结 CSP 框选导航器数字区。 |
| `engine.py` | 只做更新调度：按快捷键配置、点击区域判断哪些面板需要更新，不声称识别已完成。 |
| `catalog.py`、`shortcut_api.py` | 只读解析 CSP 保存的快捷键、工具目录、修饰键操作；配置变化约 2 s 内重载。 |
| `pipeline.py` | 每次激活都截图存证（MSS 一次采完整帧，PNG 编码在另一线程），按面板静默（画布 150 ms，其他 `analysisQuietMs`）后分析最新证据；`.clip` 稳定后复制到 `<session>.spool/<saveId>.clip` 并调用 `clip_layers_core` 解析。 |
| `state_timeline.py` | 解析预留状态包，按状态值（不含证据、时间、置信度）判断 changed/unchanged。 |
| `floating_panels.py` | 通过面板收纳程序的 `listWindows` 获取浮动面板，用 PrintWindow 截图；导航器靠底部按钮栏模板匹配对齐回初始化位置（分数 < 0.8 作废并重新初始化）。 |
| `history_reader.py` | 撤销/重做后（静默 250 ms）读取被拉长的历史记录面板，模块 `historyState`。 |

状态核心（模块名 → 实现）：

| 模块 | 核心 | 输出要点 |
|---|---|---|
| `brushState` | `recognizer_core/panel_state`（RapidOCR + 属性库 158 项） | 子工具名、属性 `key/value/type/unit`、`valueRegions`（number/icon/text 及屏幕框） |
| `subtoolState` | 子工具面板 OCR | `ocrEntries/groupEntries/toolEntries`，与工具目录匹配 |
| `currentLayerState` | `recognizer_core/layer_state` | 当前图层名；`rawResult.layerLocator.rows` 含行框与眼睛框 |
| `colorState` / `colorInputState` | `color_state` / `color_input_state` | 当前颜色；RGB 滑块数字位置 |
| `canvasViewState` | `screen_canvas_transform` 经 TransformHost | 画布原点、缩放、旋转、`screenToCanvas/canvasToScreen` 六元素仿射矩阵 |
| `clipState` | `clip_layers_core`（解析保存的 `.clip`） | 图层树（id、uuid、可见性、混合、文件夹…）、`canvas.current_layer_id`、`snapshotPath` |
| `historyState` | `recognizer_core/history_state` | 历史面板各行文字与“已撤销”状态 |

画布核心：初始化时由完整帧与 ROI 求得固定的画布视口 ROI 与导航器缩略图 ROI，之后只做 `RecomputeAsync`；特征提取/相似度/生长已多线程并逐位一致。只有画布视口或 CSP 主窗口变化才重新初始化。

### 4.3 面板收纳（virtual_panel_probe）

`PanelStashProcess` 在 Memoline 运行期间以 `panel_host.py --embedded --parent-pid` 启动它，退出时发 `shutdown`。

- 用户把 CSP 浮动面板拖到屏幕角，收纳程序把它移到虚拟显示器（上游 Virtual-Display-Driver，`vdd/install-vdd.ps1` 安装，单显示器多分辨率）；所有面板靠虚拟屏左缘堆叠，PrintWindow 仍可读取。
- 只在有面板收纳时挂接虚拟屏（至少主屏大小），最后一个面板离开 5 s 后卸下，避免反复改尺寸冻结桌面合成。
- 历史记录面板被拉长到能列出全部撤销步骤（CSP 撤销上限读自 `Config.sqlite` 的 `Performance.UndoCount`）。
- `guard.py` 把其他程序的窗口移出虚拟屏，并在面板下铺黑色最大化背板；收纳过的面板种类记入 `state.json.remembered`，下次启动自动再收纳。
- 管道 API：`\\.\pipe\MemoLine.PanelStash`（`listWindows`、`shutdown` 等，见其 README）。

## 5. 聚集层（watcher）

watcher 原是独立程序，现以源码链接进宿主，宿主通过 `WatcherHost`/`IWatcherHost` 接管会话所有权与封盘。

```
RecognizerMonitor（订阅实时管道）
   └─ RecognitionEvidence：按 triggerTicks 保留各频道状态、接触连续性
       └─ WatchState.Reserve：确认的 canvasViewState 变化 / 录制结束 / 编辑边界 → CaptureRequest
           └─ CaptureCoordinator（串行信号量）
               └─ SaveCapture：等待输入空闲 → requestClipSave(Ctrl+S) → 稳定副本 → bridge inspect → export-id 各涉及图层
                   └─ SnapshotHistory（每层两槽 After/Now）→ LayerDiff.Compare → packets/<id>/manifest.json + PNG
                       └─ AggregateSession：dimensionSample / packet / asset 追加到 aggregate-events.jsonl.part
```

要点：

- **边界**：正常边界只有“确认的画布视口变化”（`boundaryKind=canvasViewportChanged`），每次都生成一个包，没有图像也保留带原因的空包；另有 `recordingEnd`（主末包）、`recordingEndLayer`（其他图层副包）、`editBoundary`、`memolineOperation`。
- **记艺线操作包**（`memolineOperation`，2026-10-20）：每次执行成功的编辑结束时，按被替换的每个图层封一个侧包（`SnapshotHistory.RecordOperation` → `AggregateSession`，封在原生 `editingActionCompleted` 帧上，像编辑边界包一样只含 context 指针、不占主窗口）。内容是被替换图层最后一张快照 → 复现层安装基线的差异；`manifest.memolineOperation` 记 `transactionId/editKind/replacedLayerUuid`。读者把它算作复现层的第一个包（`LayerPacket.Operation`），复现层的像素链因此直接接上原图层，不再需要“观察到的缺口”桥。它是该次编辑重建之包的**另一版本**（见 §8.2 版本规则）。
- **差异**：`LayerDiff` 以 64 px 格子全分辨率比较（`comparison=fullResolution/v2`），变化格子按 4 邻接成连通分量，每个分量一张脏矩阵图片（after/now/mask/difference，原分辨率裁切），`labelIds` 关联笔接触标签。
- **图层映射**：`LayerMapping` 把当前图层名映射到保存 `.clip` 的唯一图层编号；纸张图层不接受笔画；重名明确报歧义。已捕获图层按 UUID 刷新（`_capturedLayerUuids`），不按名称。
- **基线来源**（`SnapshotHistory`）：`recordingStart`（录制开始的全层保存）、`layerCreated`（录制中新建图层首次出现在某次保存时，用该保存的 spool 副本导出）、`reproduction`（编辑安装的复现层）、`createdEmpty`。普通首次捕获不自动可信。
- **编辑边界**：`EditingBoundaryCoordinator` 预留边界，一次保存导出所有自上次捕获后有笔画的图层；两道原生队列屏障检测保存期间的物理输入，任何失败都释放预留。
- **谱系证据**：`MergeDetection`（消失图层的下方图层只在其不透明区域内变化 → 合并，否则删除）；新图层若与回收站副本像素一致 → `recyclePaste`；均通过控制管道 `recordLayerLineage` 写入原生流。

## 6. 存储与封盘

### 6.1 两份运行时流

| 流 | 位置 | 内容 |
|---|---|---|
| 原生机械流 | `Recognizer/procedure/stroke/<session>.memoline.part` | 硬件帧、状态帧、截图 blob、保存请求、编辑控制帧；CRC/Brotli 帧格式 |
| 聚集流 | `.work/<会话>/aggregate-events.jsonl.part` | `header / dimensionSample / packet / asset / footer`；PNG 按 512 KiB base64 分块，按完整字节 SHA256 去重 |

另有：`edit-journal.jsonl`（编辑日志）、`<session>.spool/`（截图与 `.clip` 副本、任务描述）、诊断日志。

### 6.2 `.memoline` 容器（`BundleArchive`）

ZIP 外层，`index.json` 记录各 entry 的解压后 SHA256、字节数、`fixedSha256`（只覆盖 packet/asset 行）与活动维度入口。

| schema | 增加内容 |
|---|---|
| `memoline-csponly/v1` | 原始 ZIP entry |
| v2 | Brotli（quality 4，window 24）压缩各流，`.br` 物理名 |
| v3 | 编辑日志与其 PNG 资产 |
| v4 | `projectPath` 与 `previousSessions[]`：旧会话存为 `sessions/<机械流SHA256>.memoline`，同一工程续写同一文件 |

封盘流程：等保存/diff 任务完成 → `prepareRecordingEnd` 取原生结束事件 → 末包与各层副包 → Recognizer 写 footer → 校验时钟、时间轴、所有事件指针、包窗口从 0 连续覆盖到 footer（`endPacketPolicy=nativeFooterClosure/v1`）→ 写同目录临时容器并重新校验 → 原子改名/替换。成功才清理中间文件。

命令行：`--verify`、`--seal`、`--extract-mechanical`（导出与原生逐字节一致的机械文件）、`--compact`、`--upgrade-dimensions`。

### 6.3 工程级缓存

- `ProjectRecordingStore`：按 `.clip` 完整路径找到已有记录（读流前缀中的 CLIP 身份），不同目录同名工程用带路径摘要的文件名。
- `ProjectSessionReader`：把已封盘工程的各会话与图像解出到 `<project>.memoline.cache`。
- `RecycleBin`：`<project>.memoline.recycle`，保存编辑删除的原图层像素与图层属性，供用户从回收站粘回。

## 7. 进程间接口

### 7.1 实时管道 `\\.\pipe\MemoLine.Recognizer.<sessionId>`

UTF-8 JSONL，仅限同一 Windows 用户。连接后发送 `{"schemaVersion":1,"channels":[…],"includeSnapshot":true}`。频道：`keyboard / mouse / tablet / system / shortcuts / layers / layerstage / subtools / core.*`（`all` 为 13 个频道）。连接时回放每个核心的最新结果（失败时先回放最后成功结果）；慢客户端溢出给出 `streamGap`。C# 用 `RecorderRealtimeClient.SubscribeAsync`，命令行用 `Memoline.exe --subscribe`。

### 7.2 控制管道 `memoline-recorder-input-<pid>`

一行请求、一行响应：

| 命令 | 用途 |
|---|---|
| `getRecordingStatus` / `getInputControlStatus` | 会话就绪、输入捕获可用 |
| `requestStates{modules[], saveId?, afterEventId?}` | 主动截图/解析 1–8 个模块，不返回缓存 |
| `requestClipSave{expectedClipPath, requestId, triggerTicks?, activateCsp?}` | 派发 Ctrl+S（只确认已发出，不确认 CSP 完成） |
| `prepareEditBoundary{requestId}` | 等笔抬起，追加 `editBoundaryRequested` 并刷盘，幂等 |
| `beginEditTransaction` / `endEditTransaction{outcome}` | 接管/恢复输入拦截，追加事务帧；事务中物理输入只产生 `physicalInputDuringTransaction` 告警 |
| `prepareRecordingEnd` | 追加 `recordingEndRequested` |
| `recordLayerLineage` | 写入 `layerLineage` 帧（recyclePaste / merged） |
| `configureInputInterception` / `restoreAutomaticInputProtection` | 输入拦截策略 |

事务成功后只追加一次 `editingActionCompleted`（`editKind=eventEditing|preciseUndo`，`changes[]`（换子工具时含已确认的 `replacementBrushState`），`layerReplacements`，`replayed[]`：事务中重放过的全部录制笔接触）；回执带该帧的 `appendId/ticks`，Memoline 随即在这一帧上封记艺线操作包。事务期间的自动输入和状态不进入绘画历史。

`requestStates` 的 `clipState` 不带 `saveId` 时只是解析磁盘上 CSP 最后一次保存的文件，证据标 `saveBound=false`：撤销/重做不保存，这样的解析可能落后于当前文档，谱系不采用。

### 7.3 其他

- TransformHost：JSONL `initialize / width / height / dpi / frame / crops{workspace,navigator,numbers}`。
- clip-layer-bridge：`inspect <clip>`、`export-id <clip> <layerId> <png> <w> <h>`。
- 面板收纳：`\\.\pipe\MemoLine.PanelStash`。

## 8. 编辑子系统（`source/Editing`）

### 8.1 流程

```
Alt+M（GlobalHotkey）→ EditingPanel 选择「精确撤销 / 事件编辑」
  1. EventSelectionOverlay 冻结 CSP 所在显示器的画面（只截 CSP 客户区下的显示器），边界在背后建立
  2. DemoEditingHost：prepareEditBoundary → watcher 编辑边界捕获（保存 + 导出涉及图层）
  3. 读历史：LiveSessionReader（本次会话，读刷盘前缀）+ ProjectSessionReader（历史会话）
       → EditIndex（单会话）→ ProjectEditIndex（跨会话 + LayerLineage 路由）
  4. 用户在原画布位置框选/圈选（CanvasSelectionGeometry、CanvasInteraction 用原生 screenToCanvas）
       精确撤销：PreciseUndoSelector 选基础笔画 + 叠放闭包，显示白线路径
       事件编辑：列出跨层脏矩阵图片 → 选一张 → 光标附近白线 → 像矢量橡皮一样扫选整笔
  5. ReconstructionPlanner（纯依赖分析）→ FrozenEditPlan → 预览
  6. ReconstructionEngine + CspEditTransaction + WindowsCspEditingActions 在 CSP 中执行
       （SelectionProgressFrame 显示进度，可取消；物理输入中止事务）
  7. EditJournal 记录；复现层登记为 reproduction baseline；结束事务，恢复后台捕获
```

### 8.2 组件职责

| 层次 | 组件 | 职责 |
|---|---|---|
| 读取 | `LiveSessionReader`、`ProjectSessionReader` | 解码机械帧与包；用完整差异链重建被 watcher 删除的起始整层 |
| 时间轴 | `LayerTimeline`、`EffectiveUndoHistory`、`NativeUndoUnits`、`NativeUndoTimeline` | 每层历史游标；把 CSP 的 Ctrl+Z/重做与录制单元对应（用历史面板读数按“纪元”匹配）；图层可见性、选中图层不进 CSP 历史 |
| 索引 | `EditIndex`、`ProjectEditIndex`、`LayerLineage`、`BoundaryLayers` | 合格笔画（画布内、笔刷工具、状态非歧义、有可信基线）；新图层靠下一次保存解析（`ResolveNewLayer`）；谱系：复现层继承、回收站粘回继承、合并并入目标；无继承者的图层归入“已被删除”（默认隐藏、不可编辑）；用户 Ctrl+Z 恢复原 UUID 时撤销该继承，已消失的复现层视为从未存在（`LayerLineage.Undone`）；边界时在世的图层取边界那次保存的结构（`SessionSnapshot.BoundaryLayers`）。`MemolineEdits` 按版本规则处理已执行的编辑（见下） |
| 几何 | `Footprints`、`EditingModels`（位集）、`ImageCompositor` | 每个接触的写入/探测/因果影响足迹；mask 处整体替换 RGBA |
| 分类 | `BrushClassifier`、`ToolCatalog`、`BrushParameterContract`、`ReferenceReadEvidence`、`Resources/*.json` | 按身份判定笔刷工具；哪些数字属性在目标子工具中有可写输入框；参考图层属性的因果性 |
| 选择 | `PreciseUndoSelector`、`CanvasSelectionGeometry` | 按撤销深度选笔：写入足迹与选区相交的最新笔画，加其后触及其墨迹的笔画 |
| 规划 | `ReconstructionPlanner`、`FrozenEditPlan`、`HistoricalReferenceScene`、`UndoCapacityPolicy` | 静态两遍法的第一遍：分段、哪些合成、哪些重放、拒绝原因；层局部问题不拖累无关选区 |
| 执行 | `ReconstructionEngine`、`CspEditTransaction`、`WindowsCspEditingActions`、`EditingCoordinator` | 在线执行：粘贴复现层 → 保存校验 → 删除原层 → 保存校验 → 离散重放；图层移动按保存的结构规划（`LayerNavigation.Steps`），当前层取自保存的 `current_layer_id` |
| 记录 | `EditJournal`、`RecycleBin`、`EditTiming`、`EditingProfiler`、`EditingMemory` | 追加式编辑账本；原层回收；各步耗时写 `logs/edit-timing.log`；不在用的整层像素压缩保存 |
| 诊断 | `OfflineEditProbe` | 不连 CSP，对已封盘工程模拟精确撤销与事件编辑（`--offline-edit … --trace` 打印每个接触为何未入索引）；工程还没有封盘文件时也可配 `--live` 使用 |

**版本规则**（用户规格，2026-10-20；`MemolineEdits`）：

- 记艺线产生的事件不是用户操作。用户在 CSP 里撤销它们，它们就从未发生；整次编辑被撤回（原图层复现）时，该编辑整体忽略，复现层不出现在任何分类里。
- 精确撤销重放的笔（为了让 CSP 自己的撤销能逐笔退回）标为 `MemolineInjected`：不合格、永不被选中，也不进入以后精确撤销的闭包；之后带有它们的图片按录制像素合成。
- 事件编辑改动的笔成为新版本（`EditableStroke.Version`）：显示与选择用改后的子工具/数值与足迹，仍可再次编辑——请求在 `MemolineEdits.Effective` 中与上次修改合并成相对原录制的修改；以后任何重放（包括闭包、精确撤销的离散重放）都带上当前版本的修改。被删除的笔在当前版本中不存在（`IsUndone`）。原样重放的笔仍归原来的包。
- 记艺线操作包的图片以该次编辑重放过的笔为事件（依赖关系完整），但只提供该次编辑改动过的笔供扫选；之前只含被改动笔的图片标为旧版本（`DirtyImage.SupersededBy`），事件编辑列表默认隐藏（“显示被记艺线操作包取代的旧版本”），只读。

### 8.3 回放（packetreplayer + strokereplayer）

- `ReplayState` / `PacketReplayStateTable`：录制状态表与实时确认表只在变化时推进；选项序号不当作数字编辑框。
- `PacketStateRestorer`：工具快捷键切换 → 子工具面板 OCR 定位点击（必要时滚动搜索）→ 数字属性点击 `valueRegions` → Ctrl+A → 输入 → 回车 → 读回。
- `ColorRestorer`：写入 RGB 滑块数字并逐通道确认（须在 RGB 页并选中主色）。
- `ViewRestorer` / `PacketViewFeed` / `WindowsViewInput`：缩放/旋转输入数字，平移用空格拖动；事务中每次视图观察都是主动请求。
- `PenReplayEngine`：`InjectSyntheticPointerInput` + `PT_PEN`，使用录制时屏幕坐标（多屏时优先驱动映射的 `screenX/Y`），离散模式笔间间隔上限 0.2 s。
- `LivePacketFeed`：实时状态喂入；`ConfirmLayer` 以保存为准，屏障丢弃更早的 OCR。

## 9. 时钟、身份与一致性约定

- **单一时钟**：所有时间都是该 Recognizer 会话的相对 Stopwatch ticks（Python 用同一 QPC 原点与频率）。墙上时钟、解析完成时间、保存派发时间不作为边界。
- **指针**：`sessionId + appendId` 唯一定位原生帧；`eventPointers` 只含硬件帧，`statePointers` 指向状态帧；窗前延续的接触与上下文带 `context: true`，避免重复计数。
- **图层身份**：以 `.clip` 中的 UUID 为准，名称只作映射线索；同名图层报歧义。
- **状态可用性**：`status` 决定观察是否有效；`causalAmbiguous` 是时序诊断，但编辑索引拒绝歧义槽位，所以主动请求必须带 `afterEventId`。
- **跨会话**：各会话保留各自时钟与 appendId，不伪造连续时间轴；`ProjectEditIndex` 拼接时不改写原生身份。
- **坐标**：所有进程 PerMonitorV2；画布坐标为归一化 `[0,1]`，乘画布宽高得像素；仿射矩阵 `[a,b,c,d,e,f]` 表示 `x'=ax+by+c, y'=dx+ey+f`。
