# 真实 `.memoline` 离线选区验证

2026-10-09。使用 `.stage/history-audit-current/Release/net10.0-windows/MemolineDemo.Checks.dll` 的 `--actual-project-probe`，直接读取 `publish/win-x64/recordings/记艺线测试.memoline`。没有操作 CSP，也没有修改原文件。

**结果：历史记录已经能被选区代码读取，但这份旧文件的两种编辑计划都仍被记录缺口拦截，没有完成实际重建。** 探针正常退出只是报告生成成功，不代表编辑功能执行通过。

恢复了 7 个会话、590 个原生 `penBegin`；其中 512 个接触通过笔刷和历史状态资格校验。合并索引有 20 张图片，含一个从两次完整观察得到的缺口证据。

检查最新 80 个有图片的历史接触，在对应图片变化掩码与接触写入范围相交、且不被更晚图片覆盖的实际像素附近，分别框选 40 × 40 和 4 × 4 画布像素，共 160 个范围。

| 检查 | 实际结果 |
| --- | --- |
| 精确撤销选笔 | 160 / 160 个范围的 selector 有效 |
| 事件编辑图片选择 | 104 个范围可选；56 个范围的图片含不可重放事件 |
| 精确撤销合法重建计划 | 0 / 160 |
| 单笔删除事件编辑合法计划 | 0 / 104 |
| 真正离线重建 | 未执行，所有计划均被拦截 |
| 原生重放 schedule 验证 | 未进入，只有合法计划才会调用 |

主要阻塞是 `UnreplayableEventInMatrix`：修改需要跨过缺少完整图像或脏矩阵的历史间隔，无法确认该区间的重建结果。这个问题出现在 157 个精确撤销范围及全部 104 个可选图片的事件编辑计划中。部分范围还存在更早记录的 `UndoRedoInRange` 或不可重放矩阵；这些理由可能同时出现。

一个可复查的例子：画布范围 `(1390,1188)–(1430,1228)`，实际可见像素 `(1410,1208)`，源接触为会话 `4cd6b862a09449beaac155f15c3b308d` 的 `BeginAppendId=50357`、`BeginEventId=40322`。该图片可选择；精确撤销选中 17 笔，事件编辑单笔删除选中上述 1 笔，但两计划均因缺尾图像/脏矩阵间隔被拦截。

尾部审计已经确认最后完整捕获之后仍记录了 84 个 `penBegin`，封盘包却为 `empty`，原因是 `recordingEndLayerOrCanvasUnconfirmed`。因此这里的缺口指缺少这些已有原生事件对应的末尾图像与脏矩阵证据，不是断言用户进行了未记录的操作。原始尾部证据见同目录 `recorded-tail-summary.json`。
