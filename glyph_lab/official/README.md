# CSP 官网 UI 截图实测 · 2026-11-13

本次收集并实际测试了 CSP 官方说明书截图。**现有字形程序尚不能可靠读取这些真实 UI；此前合成测试的 1 ms/字成绩不能作为上线依据。**

可直接打开 [逐条图文报告](results.html)，筛选误识、拒识、语言和文字/数字，并查看原图裁切、标注、预测、候选及官方来源。HTML 已内嵌测试裁切，可离线阅读。

## 收集与标注

- 官方来源：`https://help.clip-studio.com/`，英文、繁体中文、日文共 **14 个页面、56 张原图**，约 4.42 MB。
- 范围：工具属性、工具详细设置、图层、颜色滑块、导航器/画布。
- `sources.json` 保存每张图的官方页面、图片 URL、原始尺寸、HTML 标示尺寸、字节数和 SHA-256。原始图片和 HTML 在 `raw/`，不缩放、不重编码后保存。
- 从 21 张图中目视转录 **267 个区域**：3 张图、50 个区域用于选字体候选；另外 18 张图、217 个区域用于测试，两组无相同文件或文件哈希。
- 测试有 **144 种不同像素裁切、125 种文本**。跨语言截图中的颜色通道和零值有重复，不是 217 个独立随机样本。
- 文字包括普通面板标签、用户图层名、单字母颜色通道、小标题；数字包括整数、小数、负数和百分数。小标题及手册局部放大图单独标记，当前程序不会自动选择多字号。
- 标注依据是截图目视阅读，并逐条放大检查裁切；没有用 OCR 或模型预测作为答案。标注仍需另一位人类独立复核。数字将排版空格去除，减号用 ASCII `-` 表示。

## 固定阈值的结果

识别算法、默认阈值 0.84、分差 0.04、top-k 16 均未改动。整词识别使用项目原有 `csp_strings.sqlite3` 对应语言的全词库，**没有把测试答案补进词库**；数字用单字符模板。

| 配置 | 正确 | 误识 | 拒识 | 区域总数 |
| --- | ---: | ---: | ---: | ---: |
| 原有 Mac 宋体 18 px 预设，按语言换完整词库 | 0 | 0 | 217 | 217 |

第二组的 **10 个正确结果全部为单个拉丁字母**，整词和数值均未通过。它是诊断性对照，不是验证通过的字体配置，也未自动应用到日常工作台。

计时在 Apple M5 / macOS 26.5、Python 3.12.13 上进行，每组预热后 5 轮，包围完整 `recognize()` 调用；分母使用真值字符数，不含读图、人工框选、字体选择和建库。**大量样本提前拒识，因此这些低于 1 ms/字的耗时不代表任务达标。** 下载/选框后的整个图像管线尚未验收。

## 暴露的问题

1. **实际字形尚未适配。** 在 50 个校准区域上，本机候选字体几乎没有可靠识别。候选包含宋体、Arial、Tahoma、Arial Unicode、冬青字体，字号 10–15 px；词表文字均为 0 个正确匹配。仓库旧实验指出官网旧截图最接近 Windows `MS UI Gothic`，本机未找到这款字体，本次不能把这一旧结论当成对所有新截图的确认。字体、字号和栅格化方式均需用真实环境复核。
2. **数字可以被错误拆开。** 使用不匹配的 Songti 12 px 时，5 个 `0` 区域被接受为 `1.1`，另一个 `10` 被接受为 `11.1`。前 5 处是重复的零字形，共涉及两种数值模式，不是 6 种独立错误。数字路径允许把一个字符的笔画解释成多个字符，单靠相关得分和语法没有挡住。失败样本已固定到 `failures.json`，尚未修复。
3. **字号需要按区域区分。** 标题小字、普通正文、手册放大框与数字并非一个字号。现有每次只配一套字体/字号的接口，无法自动处理这种混合。
4. **词库需要与软件版本和用户工具库同步。** 全量翻译资源仍不包含所有图层名和当前手册标签；词库外文本需要明确拒识或另一路处理。

后续应先在 Windows 上用真实 `MS UI Gothic` / GDI 字体做同一数据集的对照，并补数字字符间距与整体宽度约束，再评估真实截图的识别率和延迟。截图测试证明当前程序还需要这些工作，不能直接替换生产 OCR。

## 复现

在仓库根目录、已安装 `glyph_lab/requirements.txt` 的 Python 环境执行：

```bash
# 收集可断点复用缓存；验证 HTTPS，失败重试，不关闭证书验证
python -m glyph_lab.official_csp collect

# 按50个校准区域比较当前 Mac 的已安装候选字体
python -m glyph_lab.official_eval calibrate

# 使用项目资源库，以217个测试区域评估；校验原图哈希及分组隔离
python -m glyph_lab.official_eval evaluate --rounds 5

# 根据最新结果重建可视化报告与已知失败集
python -m glyph_lab.official_report
```

若来源页结构改变，收集器会在 `sources.json` 的 `errors` 中记录；要复现本次样本，使用保存的原图并保留清单中的校验值。原图仍由 CSP 官方持有，本地收集用于此项目测试。

可以手动提供已核实的字体配置：复制 `calibration.json` 的 `profiles` 字段，在 Windows 上把各语言的 `words` / `numbers` 配置改为 `{"source":"MS UI Gothic","px":12,"index":0,"backend":"gdi"}`，然后运行：

```bash
python -m glyph_lab.official_eval evaluate --profiles verified-fonts.json --rounds 5
```

这只是验证用的起始候选，不能预先保证所有截图都用同一字号。字体候选扫描目前是 Mac 专用；评估器和图像数据可以跨平台复用。运行会更新 `report.json` / `runs/cases.json`，对比实验请先复制原报告。

`annotations.json` 是原图坐标标注；`calibration.json` 是校准结果；`report.json` 是精确汇总及运行环境；`runs/cases.json` 是逐条预测；`failures.json` 是已知误识清单。采集原图、校准图和测试图可以相似，按图隔离不能当作独立来源或全新软件版本的盲测。
