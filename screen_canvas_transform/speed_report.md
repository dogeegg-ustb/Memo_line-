# 重算速度优化验证（2026-09-22）

优化前基线已推送到 GitHub main：`4d35395`，提交名“坐标转换已实现，优化速度中”。

## 修改范围

- 画布观察：同一次调用中，使用带完整 24 位 BGR 键校验的 4096 槽直接映射缓存，复用相同颜色的背景分类结果。哈希碰撞执行原始 Lab/DeltaE 运算，没有颜色量化、阈值变化或跨帧模型复用。
- 连通区域：背景遍历结束后复用其队列存储，减少扩容和逐分量分配；访问顺序和判定保持一致。
- OCR：保留四阈值、反色、原图的全部六种候选，以及联合区域兜底。只在实际六倍重采样后的输入字节、ROI 坐标、识别语言完全一致时复用结果，包含 ROI 边缘插值影响。变化区域重新识别，空结果不缓存；输出 CaptureId 和时间戳按当前帧重新创建。
- OCR 缓存最多 8 项，每项不超过 4 MiB；更大的区域正常识别而不缓存。
- OCR 中间 PNG 默认不保存；设置环境变量 `SCT_OCR_DEBUG=1` 可恢复原调试输出，并旁路缓存。
- 增加 `[Perf]` 日志：截图、工作区观察、导航器观察、OCR、红框、矩阵求解和重算总时长。
- 修正原生 DLL 的复制优先级，避免旧 build_src 产物覆盖 app/Native 中的新版本。

未改红框精修/几何求解、识别阈值、OCR 候选排序、截图方法或 120 ms 覆盖层消隐等待；没有使用上一帧数值猜测当前缩放/旋转，也没有引入 GPU 依赖。

以下是当前机器上的阶段测量，不是整次重算总时长承诺。原生测试同一进程加载旧 precision DLL 和新 DLL，预热后各运行 5 次取中位数，序列化全部观察结果字段并比较完全相等。

| 340×330，大块纯色导航器 | 23.95 ms | 2.35 ms |

| 340×330，画布填充随机彩色纹理 | 25.76 ms | 17.26 ms |

OCR 新建服务全量识别与共享服务对比：

- 重复输入：约 330–377 ms → 6.3 ms。
- 只改变缩放数字：384.1 ms → 202.9 ms。
- 只改变旋转数字：400.6 ms → 205.2 ms。
- 改变 ROI：重新识别，未错误命中旧位置。
- 空白失败输入：仍完整重试，约 537–546 ms，没有用旧成功值顶替。
- 所有用例的数值、原文、置信度均与全量路径一致，CaptureId 为当前帧。
- 合成字体用例中的 `27.5` 在原流程和新流程都被读成 `5`；该用例只验证行为等价，不计为绝对识别正确。此原有 OCR 问题不在本次速度优化中调整。
