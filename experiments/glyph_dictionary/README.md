# 字形字典与字体验证实验（2026-11-10 ~ 11-11）

一次性实验脚本，没有接入正式识别流程。原本放在本机临时目录（`%TEMP%/glyphtest`、`%TEMP%/fontver`），
路径大多写死在本机，换机器要改脚本开头的路径。截图、裁切、结果数据都没有提交（含 CSP 资源和用户画面）。

| 脚本 | 作用 |
|---|---|
| `gdi_match.py` | Windows GDI 渲染文字（宋体等，灰度抗锯齿），灰度归一化相关匹配 |
| `coarse.py` | 粗筛：文字框缩到 24 px 高，4 个笔画朝向 × 4×40 网格 = 640 维向量，一次矩阵乘法比完全部词条 |
| `run.py` | 最早的 13 个裁切对照（宋体 / 雅黑 / 黑体） |
| `collect.py` | 从录制器 spool 汇总并去重面板截图 |
| `big2.py` → `exp6.py`，`analyze2.py` | 大规模实验：504 张实时面板、6028 行，以 OCR 为对照 |
| `atlas.py`、`live_icons.py`、`icon_src2.py` | 图标图集版式分析、在实时截图里找图标、定位图集在 CSP 文件里的位置 |
| `font_fetch.py`、`font_fontcheck.py`、`font_knowncheck.py`、`font_strict.py` | 下载官网各语言说明书截图，比对候选字体 |

## 结论

- 宋体 18 px（150 %）、21 px（175 %）对得上实时面板文字；雅黑对不上。
- 大规模（exp6）：词典内 1349 行有 82 % 由字形直接认出，认错 0 个，其余交给 OCR；
  词典外 2587 行没有被认成别的词；每行 3–5 ms，OCR 只做识别约 14 ms。
  关键处理：局部中值滤波去背景（|gray − medianBlur|），删掉超过 1.2 个字长的直线（边框/滑块），
  文字框取一字高的行带，候选必须盖满文字框（否则「不透明」会顶替「不透明度」）。
- 字体：官网英/法/德/西/日/繁中说明书截图里，最匹配的都是 MS UI Gothic 12 px（日文 Windows 的默认界面字体）。
  CSP 用的是 Windows 默认界面字体（DEFAULT_GUI_FONT），不按 CSP 语言换字体。韩文版、非中日文 Windows 未验证。
