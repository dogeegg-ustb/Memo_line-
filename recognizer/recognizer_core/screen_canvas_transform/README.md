# ScreenCanvasTransform.Core

Windows x64 / .NET 8 的独立画布坐标转换核心，2026-10-03 从已收尾的 ScreenCanvasTransform 程序同步。沿用原核心的 public API、命名空间和程序集名；Recognizer 的 TransformHost 直接引用本项目。

核心接收调用方提供的 Bitmap、物理屏幕原点、ROI 和画布文档尺寸，返回画布原点、缩放、旋转、变换矩阵及失败阶段。保留初始化、冻结锚点重算、三裁剪兼容入口和存档接口。窗口、截图采集、覆盖层、UI 进度和调试文件输出不在核心中。OCR 模型目录由调用方通过 `RapidOcrModelDirectory` 提供。

## 独立构建与测试

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./build.ps1
```

需要 Visual Studio x64 C++ 工具及 .NET SDK。脚本只读取本核心目录的源文件，重建捆绑的 ScreenCanvasNative.dll，运行五组原生回归测试，再构建托管核心并运行 Tests。NuGet 包需已缓存或可访问包源。无需 WPF 项目，也无需原程序目录。`-SkipTests` 仅用于已有验证结果的构建。

`native/workspace_border` 是当前原程序实际使用的工作区边界算法副本；`native/tests` 保留本轮修复后的原生测试。托管测试覆盖 OCR 数字拼接、存档、坐标转换、核心输入约束和实际 P/Invoke 求解。SmokeTest 保留原来的手工截图验证入口。

## 替换 Recognizer 的核心

从仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File recognizer/recorder_integration/update-transform-core.ps1
```

这会重建并测试核心，发布 TransformHost，更新 Recognizer 发布目录和 Release 构建目录中的 `integration/transform_host`，校验原生 DLL、托管核心和宿主程序集哈希。调用协议、设置和其他识别核心继续沿用现有版本。完整 Recorder 发布脚本也会先构建并测试本核心。

部署后自动运行 JSONL 宿主冒烟测试：损坏输入不会中断进程，负坐标完整帧进入原生管线并返回结构化失败，失败初始化后不能继续重算。

2026-10-03 验证结果：独立构建的五组原生回归全部通过，25/25 托管测试通过；Recognizer 发布目录和 Release 构建目录中的新宿主均通过上述冒烟测试，部署 DLL 哈希与核心构建输出一致。实机 CSP 图像识别效果沿用上一轮的验证边界，未在此次部署中重新执行交互验收。
